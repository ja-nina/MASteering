Steering mini report

What this isPersona-vector steering of LLM agents in multi-agent games, in plain terms: 9 games (game × text or image), 8 personas. The full report (report.html) has the statistics behind every line.How to read itCharts: the steering strength c on the x axis (negative = pushed away from the persona, 0 = unsteered), one line per setting. Words: markers ●●● solid (p < .001), ●●○ tentative (p < .01; with this many comparisons some are chance), ●○○ no clear change, ○○○ too little data. Results are the game's own (wins, or the score in the game's units), always against the same seats in unsteered games with the same seeds.How the monitor reads language
  1. A second, unsteered copy of the model reads every turn. The same model, on its own GPU, is given the agent's exact prompt and answer (image turns with their images) as a prefill, as if it had written them itself; it generates nothing new.
  2. It records the hidden states (the residual stream after each decoder block) of every token, with vLLM-Hook.
  3. Only the answer counts: the prompt's tokens are dropped and the answer's hidden states averaged, one vector per turn.
  4. Projected on each persona: that vector's dot product with the unit-length PersVecFast vector of each of the 0 monitored personas, one number per persona: how strongly the model represents that persona in what the agent wrote.
  5. Per agent and episode: the mean over its turns at the monitor layer (and per third of its turns, for section 14).
  6. Scaled to the unsteered agents of the same game: 0 = a typical unsteered agent, +1 = one standard deviation more of the persona.
Because the reader is unsteered, it measures what the text conveys, not the injected vector, which is why it can read prompted agents too. Its limits: the persona vectors overlap, so one number never means one trait alone (sections 3, 17), and answer length and style leak into it (section 20).

Prompt, vector, or both: do they reinforce each other?

Games played for these results (9): avalon_6p, avalon_6p (image), gbs_3p, gbs_3p (image), gbs_6p, gbs_6p (image), harvest_5p, harvest_5p (image), iterated_ultimatum_2p

One agent, the vector at c = ±1 (the prompt has no strength). Each is compared with the same unsteered games, so if the two simply add, 'both' = vector + prompt. Verdict: more than the sum (synergy), adds up, or less than the sum (they overlap or compete; on the language this can also be a ceiling). 'All games' pools every game; 'text' and 'image' use only the games played both ways, so the two compare the same games. 'Games' counts the verdict game by game (more / adds up / less): pooling averages over games, so a reinforcement in one game and an overlap in another can cancel out. The pooled language verdicts allow for the games differing (random effects over the per-game results), so they say 'more' or 'less' only where that holds across games.

What steering looks like: matched examples

What you seeFor each trait, games where the same seat's first answer can be compared across conditions: same game, same seed, so the agent received exactly the same prompt; the only difference is the steering. Columns: unsteered; persona vector at c = -2 and 2; a random direction of the same norm at c = 2 (control); the persona prompt (+ / −). Second row: the same seat 4 answers in (or its last, if the game is shorter), when the games have diverged: does the persona hold, fade, or derail? The number under each answer is that turn's readout of the trait (raw projection, higher = more of the trait; compare within a row). Each trait shows different games where possible, and one game played from images with the pictures the agent saw (redrawn from the episode's seed and the logged moves; shown only when the redrawn prompt matches the logged one).Why it mattersThe tables below are averages over thousands of turns; these show what a slope of the readout actually corresponds to in text, including where strong steering stops being 'more of the trait' and becomes caricature or broken output.

Steering mini report

What this isPersona-vector steering of LLM agents in multi-agent games, in plain terms: 2 games (game × text or image), 8 personas. The full report (report.html) has the statistics behind every line.How to read itCharts: the steering strength c on the x axis (negative = pushed away from the persona, 0 = unsteered), one line per setting. Words: markers ●●● solid (p < .001), ●●○ tentative (p < .01; with this many comparisons some are chance), ●○○ no clear change, ○○○ too little data. Results are the game's own (wins, or the score in the game's units), always against the same seats in unsteered games with the same seeds.How the monitor reads language
  1. A second, unsteered copy of the model reads every turn. The same model, on its own GPU, is given the agent's exact prompt and answer (image turns with their images) as a prefill, as if it had written them itself; it generates nothing new.
  2. It records the hidden states (the residual stream after each decoder block) of every token, with vLLM-Hook.
  3. Only the answer counts: the prompt's tokens are dropped and the answer's hidden states averaged, one vector per turn.
  4. Projected on each persona: that vector's dot product with the unit-length PersVecFast vector of each of the 53 monitored personas, one number per persona: how strongly the model represents that persona in what the agent wrote.
  5. Per agent and episode: the mean over its turns at block 16 (and per third of its turns, for section 14).
  6. Scaled to the unsteered agents of the same game: 0 = a typical unsteered agent, +1 = one standard deviation more of the persona.
Because the reader is unsteered, it measures what the text conveys, not the injected vector, which is why it can read prompted agents too. Its limits: the persona vectors overlap, so one number never means one trait alone (sections 3, 17), and answer length and style leak into it (section 20).
